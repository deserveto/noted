# Noted 2.0.1 beta — build 4

Prepared on November 5, 2026 from current `main` (`ff9aac56e5762e774c36fbdaf03af7299b70bb7e`) plus the updater implementation. The user's follow-up authorized deployment/release and changed eligibility to open enrollment for every signed-in Noted account.

## Implementation and local verification

1. Integrated the updater into a clean managed worktree based on current `main`, retaining the latest workspace, sharing, image, connections and delete/undo corrections. Preserved unrelated edits in the original checkout.
2. Removed individual tester enrollment. All new and existing server-validated sessions can discover compatible published Android beta builds and request downloads. Anonymous/invalid sessions cannot.
3. Assigned source version `2.0.1+4`, a unique higher Android build than the previously distributed `2.0.0+3`, and added the release-specific structured changelog.
4. Downloaded the previously distributed v2.0.0 APK and verified its signature against the established certificate SHA-256 `934751720dcf265118d7ba8b5ec484c384bc0e1d257f8cdfb35d6bfa313e5f6b`. The new APK must pass the same independent pin before publication.
5. Ran `npm ci`, `npm test` (124 passed after adding size preflight coverage), `flutter pub get`, `flutter analyze --no-pub` (zero issues), and `flutter test --no-pub` (255 passed, including existing goldens).
6. Built the signed universal APK with `flutter build apk --release --dart-define-from-file=.env.supabase.json --dart-define=NOTED_UPDATE_CHANNEL=beta`. The first uncompressed candidate was 67,738,395 bytes and hit the live project's global Storage size limit. Publication stopped before creating an object or metadata row. The release uses Android's supported native-library compression and an explicit publisher size preflight; version/build remain `2.0.1+4` because no build-4 artifact or metadata was published. Android compatibility starts at SDK 24.
7. Checked all six Edge Function entry points using Deno 2.9.6 with an explicit functions config and lockfile, avoiding accidental dependency discovery in parent directories. Publication tooling syntax and diff whitespace checks pass.

Final compressed universal APK: **31,245,175 bytes** (29.8 MiB reported by Flutter), SHA-256 `445c1aa5461dfcc452dc55cd67d6dcd243e009ce6b4bd5ded8c544ccf66f9c24`. All three supported ABIs remain present, and the independently pinned signature verifies. The initial oversized candidate was never published.

## Deployed infrastructure and protections

- Used Supabase CLI 3.0.0 against the already-linked Noted project. A dry run showed exactly one pending migration; all 13 previous migrations were already applied.
- Applied only `20261105000001_beta_app_updates.sql`, using `--skip-vault`. Existing secrets, Auth configuration, note data, attachment buckets and other functions were not changed.
- Deployed only the `app-updates` Edge Function, with gateway JWT verification disabled because every request's account token is independently validated server-side through `auth.getUser`.
- Confirmed the private APK bucket, denied client publication/direct metadata access, and absence of an enrollment table.
- Created the GitHub `beta-release` environment with required owner review, main-only deployment eligibility, five encrypted signing/publication secrets and four public configuration variables, including the APK size budget. Credentials were supplied through private process memory/stdin, never committed or printed. The sole-maintainer environment permits self-approval; disable that when another maintainer can review releases.
- Protected `main`: pull requests and successful backend/Flutter checks are required, enforcement includes administrators, and force pushes/deletion are disabled.

The first updater-enabled APK is intentionally available as a public GitHub prerelease bootstrap. Anyone can install it, then register/sign in. Later in-app downloads use authenticated short-lived links from private Supabase Storage. The publicly downloadable bootstrap does not expose account information or change bucket privacy.
